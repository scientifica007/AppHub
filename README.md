# AppHub

بوابة عربية لفهرسة تطبيقات الويب وعرضها، قابلة للنمو مع كل تطبيق جديد. بُنيت بـ HTML وCSS وJavaScript دون اعتماديات تشغيل أو خادم خاص، مع دعم RTL والهاتف والحاسوب.

## الوظائف

- واجهة عربية بخط IBM Plex Sans Arabic محلي، ومظهر فاتح وداكن.
- مجالات قابلة للإضافة والتعديل، وبحث يتسامح مع التشكيل واختلاف الهمزات.
- بطاقات وقائمة، ترتيب حسب التمييز أو التاريخ أو الاسم، وتصفية حسب المجال والحالة.
- مفضلة محلية لكل متصفح، وتفاصيل لكل تطبيق، وروابط فتح مباشرة.
- محرر مرئي مستقل في `admin.html` لإضافة التطبيقات وتعديلها ونسخها وحذفها من المسودة.
- استيراد وتصدير JSON، والتحقق من بنية البيانات والروابط والتواريخ.
- حالات «متاح الآن»، «نسخة تجريبية»، و«قريبًا»؛ إمكانية التمييز والإخفاء وترتيب الظهور.
- اختبارات وتحقق من الفهرس قبل النشر بواسطة GitHub Actions.

الفهرس الحقيقي يبدأ **فارغًا** لأن روابط التطبيقات لم تُقدّم بعد. زر «شاهد شكل الفهرس» يعرض ست بطاقات توضيحية مع تنبيه صريح؛ لا تدخل الأمثلة في الفهرس أو التصدير، ولا تدّعي وجود تطبيقات فعلية.

## التشغيل على GitHub Pages

1. افتح إعدادات المستودع ثم **Pages**: <https://github.com/scientifica007/AppHub/settings/pages>
2. في **Build and deployment → Source** اختر **GitHub Actions**.
3. افتح **Actions → Validate and deploy AppHub → Run workflow** واختر `main`، أو أعد تشغيل النشر الأول إذا فشل قبل تفعيل Pages.
4. الرابط المتوقع بعد نجاح النشر: <https://scientifica007.github.io/AppHub/>. وجود الرابط في README لا يعني اكتمال النشر؛ تأكد من نجاح وظيفة `deploy`.

تفعيل Pages يتم مرة واحدة. بعده ينفّذ أي تعديل على `main` الاختبارات وبناء الموقع ونشره تلقائيًا. لا توضع مفاتيح وصول في الواجهة. تمنع وظيفة البناء نشر فهرس غير صالح.

## إضافة تطبيق دون تعديل التصميم

1. افتح الموقع واختر **إدارة الفهرس** ثم **إضافة تطبيق**.
2. أدخل الاسم، الرابط، الوصف، المجال، الحالة، الأيقونة واللون.
3. اختر **حفظ في المسودة**. التاريخ بصيغة `dd/mm/yyyy` في المحرر، ويُخزن بصيغة `YYYY-MM-DD`.
4. استخدم **معاينة المسودة** لمشاهدة النتيجة في نفس المتصفح. هذا لا ينشرها.
5. اختر **تصدير ونشر الفهرس → تنزيل الفهرس** لتحصل على `apps.json`.
6. ارفع الملف إلى مجلد `data` في هذا المستودع، واستبدل الملف الحالي، ثم **Commit changes**. إذا غيّر المتصفح اسمه إلى `apps (1).json` فأعد تسميته إلى `apps.json` قبل رفعه.
7. انتظر نجاح سير العمل ثم حدّث الموقع.

يمكن تعديل `data/apps.json` مباشرة على GitHub. لا حاجة لتغيير HTML أو CSS لإضافة تطبيق أو مجال. عند وجود محررين متعددين، راجع أحدث نسخة منشورة قبل رفع فهرس كامل كي لا تستبدل تعديلًا أحدث.

## بنية الفهرس

المصدر الوحيد للعرض المنشور هو `data/apps.json`. يحتوي `schemaVersion: 1` وقائمتي `categories` و`apps`.

مثال **غير مدرج** في بيانات الإنتاج:

```json
{
  "id": "my-first-app",
  "title": "اسم التطبيق",
  "description": "وصف مختصر يوضح ما يقدمه التطبيق ولمن صُمم.",
  "category": "education",
  "url": "https://example.com/my-app/",
  "status": "available",
  "icon": "book",
  "color": "green",
  "tags": ["تعليم", "تدريب"],
  "featured": true,
  "visible": true,
  "addedAt": "2026-10-22",
  "order": 0
}
```

| الحقل | الاستخدام |
| --- | --- |
| `id` | معرّف ثابت وفريد من حروف إنجليزية صغيرة وأرقام وشرطات. لا تغيّره كي تبقى المفضلة مرتبطة بالتطبيق. يولده المحرر تلقائيًا. |
| `category` | معرّف مجال موجود في قائمة `categories`. |
| `status` | `available` أو `beta` أو `coming-soon`. |
| `url` | رابط HTTP/HTTPS دون بيانات دخول؛ يسمح بالرابط الفارغ للتطبيق القادم فقط. لا يظهر زر فتح للتطبيق القادم حتى لو أُدخل رابط. |
| `icon` | مثل `book`, `layers`, `tools`, `game`, `atom`, `file`, `chart`, `globe`, `code`, `grid`. |
| `color` | `green`, `blue`, `orange`, `purple`, `rose`, `sand`. |
| `featured` | علامة «مميّز» وتقديم التطبيق عند اختيار الفرز الافتراضي. |
| `visible` | إظهار البطاقة أو إخفاؤها. الإخفاء ليس حماية للبيانات. |
| `order` | العدد الأصغر يُقدّم داخل مجموعة التمييز نفسها؛ يمكن للزائر اختيار ترتيب آخر. |

المجال يتضمن `id`, `name`, `description`, `icon`, `color`. أضفه من تبويب **المجالات** في المحرر.

## الحفظ والخصوصية

- المحرر أداة لتحرير ملف الفهرس، وليس نظام إدارة بخادم وحسابات. مجرد فتحه لا يمنح صلاحية تعديل GitHub.
- المسودة والمفضلة والمظهر محفوظة في `localStorage` لهذا المتصفح، ولا تتزامن تلقائيًا بين الأجهزة؛ قد تزول بمسح بيانات الموقع أو إغلاق جلسة خاصة.
- التنزيل والحفظ والمعاينة لا تنشر التعديلات. النشر يتطلب تعديل المستودع بصلاحيات حساب GitHub.
- `visible: false` يخفي البطاقة فقط. بياناتها تبقى عامة في المستودع وملف JSON؛ لا تخزن أسرارًا أو معلومات شخصية خاصة.
- لا يوجد تتبع للزوار أو تحليلات أو خطوط محمّلة من خدمات خارجية وقت التشغيل.
- روابط البحث والتصفية قابلة للمشاركة عبر معاملات URL. معاينة المسودة تعتمد على بيانات المتصفح المحلي، فلا تصلح لمشاركة نسخة خاصة مع الآخرين.

## التطوير والتحقق

يتطلب التحقق والبناء Node.js 20 أو أحدث؛ لا حاجة إلى `npm install`.

```bash
npm test
npm run check
npm run build
python3 -m http.server 8000 --directory dist
```

افتح `http://localhost:8000/`. لا تفتح `index.html` عبر `file://` لأن وحدات JavaScript وJSON تحتاج خادم HTTP. المشروع قابل للنقل إلى أي استضافة ملفات ثابتة؛ المسارات نسبية لتدعم مجلد GitHub Pages الفرعي.

| المسار | الوظيفة |
| --- | --- |
| `index.html` | واجهة الزائر |
| `admin.html` | محرر الفهرس المحلي |
| `data/apps.json` | البيانات المنشورة |
| `assets/catalog.js` | التحقق والبحث والمساعدات المشتركة |
| `assets/main.js` | التصفح والفلاتر والمفضلة والتفاصيل |
| `assets/admin.js` | تحرير المسودة والاستيراد والتصدير |
| `assets/demo.js` | أمثلة العرض المنفصلة عن الإنتاج |
| `assets/styles.css` | التصميم المتجاوب والمظهران |
| `scripts/` | التحقق وتجهيز مجلد النشر |
| `tests/` | اختبارات قواعد الفهرس والبحث وسلامة الروابط |

الخط IBM Plex Sans Arabic مشمول برخصة SIL Open Font License؛ النص الكامل في `assets/fonts/OFL.txt`. الأيقونات والأشكال الهندسية SVG/CSS محلية.
